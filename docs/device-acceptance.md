# iPhone 16 Pro acceptance checklist

Use a well-lit, permitted test space and replaceable data. Until this checklist passes, do not use the app as the only recorder for an irreplaceable capture. Do not use it for navigation.

1. **Install and start.** In Xcode choose your signing team, use a bundle identifier you can keep, and run on the LiDAR phone. Check the signed build's provisioning expiry. Launch that exact build online once, grant camera access and record the build and iOS versions. Detach Xcode, start from the Home Screen, enable Airplane Mode and separately turn off Wi-Fi.
2. **Short scans.** Record two overlapping segments with distinct, fixed landmarks. Check flashlight and mesh overlay, normal/limited tracking messages and checkpoint status. Verify ordinary save, then open 3D, plan, profile and section. Test denying and then restoring camera access separately.
3. **Interruptions.** Test a tab change, screen lock, app switching and force quit independently. Wait for the first completed recovery before forcing a quit. Repeat while a save is in progress. Note the last visible completed checkpoint and the recovered coverage. Do not uninstall the app while its data is the only copy.
4. **Independent backup.** From **Export scan** create a ZIP, save it in Files and transfer it off the phone. On Mac, run `unzip -t` and run `shasum -a 256 -c SHA256SUMS` inside the extracted folder. Restore the native file from Files into CavernSeer from a cold start and while already open. Reopen OBJ in a separate mesh viewer.
5. **Accuracy and endurance.** Measure a real span with a tape measure; compare against each OBJ in meters. Align copies of the two overlapping meshes on Mac using at least three distinct non-collinear correspondences and fixed scale. Check a fourth landmark not used for fitting. Record discrepancy and transform separately from the untouched ZIPs. Then repeat capture at 10 and 20–30 minutes, recording memory pressure, thermal warnings, storage used, checkpoint latency and any interrupted scan. Repeat a low-space test only with disposable data.

A phone's saved mesh is not raw ranging data; tracking can drift, especially in long, dark, repetitive or reflective spaces. Local heading is arbitrary and the mesh is not georeferenced. A successful checkpoint proves that a file was saved, not that all geometry is accurate or that all recent frames survived.
